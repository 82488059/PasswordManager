# 05b 浏览器扩展设计（Chrome / Edge / Firefox，Manifest V3）

## 1. 目标与边界
- 在 Windows 上的 Chrome、Edge、Firefox 中识别登录表单、填充用户名/密码、提示保存新凭据，并提供弹出窗口搜索/复制。
- 扩展是**无保险库的瘦客户端**：所有凭据读写、URL 匹配、密码生成、剪贴板操作都由桌面应用完成，扩展经 Native Messaging + 加密通道（见 03 §4）请求。
- 不支持：Safari；Android 上的扩展（Android 浏览器不支持 Native Messaging，Android 统一走 AutofillService，见 05）。

## 2. 代码结构与多浏览器打包
```
browser-extension/
├─ src/
│  ├─ background/        # 通道、会话、路由、标签页状态、保存暂存
│  │  ├─ channel.ts      # connectNative + 配对/握手/信封
│  │  ├─ router.ts       # content/popup 消息路由与权限检查
│  │  └─ tabs.ts         # 每个 tab/frame 的匹配摘要缓存（无密码）
│  ├─ content/           # 表单识别、字段图标、填充、提交捕获
│  ├─ inline-menu/       # 扩展页面（web_accessible），内联条目菜单
│  ├─ notification-bar/  # 扩展页面，保存/更新提示条
│  ├─ popup/             # 工具栏弹出窗口
│  ├─ options/           # 设置页（配对、行为开关）
│  └─ shared/            # 消息类型、URL 工具（仅展示用）、i18n
├─ _locales/zh_CN/messages.json, _locales/en/messages.json
├─ manifests/chromium.json   # Chrome + Edge
└─ manifests/firefox.json
```
构建：Vite 按目标输出 `dist/chromium` 与 `dist/firefox`；代码统一使用 `browser.*`（`webextension-polyfill`）。

### 2.2 Firefox 差异
| 项 | Firefox |
|---|---|
| 后台 | MV3 使用 `"background": { "scripts": ["background.js"] }`（事件页），无 SW 回收问题但仍需处理挂起 |
| 扩展 ID | `"browser_specific_settings": { "gecko": { "id": "passwordmanager@<域名>", "strict_min_version": "128.0" } }` |
| 宿主清单 | 用 `allowed_extensions: ["passwordmanager@…"]`，注册表路径不同（见 §8） |
| 权限 | MV3 中 `host_permissions` 为可选授予，首次运行引导用户在附加组件管理器中授予“所有网站” |
| 无 `offscreen` | 背景页本身可使用 DOM API |
| `use_dynamic_url` | 不支持，忽略 |

## 3. 内容脚本：登录表单识别

### 3.1 字段分类（打分制）
| 信号 | 用户名分 | 密码分 |
|---|---|---|
| `autocomplete="username"` / `"email"` | +100 | |
| `autocomplete="current-password"` | | +100（登录） |
| `autocomplete="new-password"` | | +100（注册/改密，触发生成器） |
| `autocomplete="one-time-code"` | 标记为 OTP 字段（可填动态码，见 §13） | |
| `type=password` | | +80 |
| `type=email` / `type=tel` | +40 | |
| name/id/placeholder/aria-label/关联 `<label>` 含 `user, login, email, account, 账号, 用户名, 手机, 邮箱` | +30 | |
| 含 `pass, pwd, 密码, 口令` | | +30 |
| 含 `search, captcha, 验证码, coupon` | −100 | −100 |
| 位于密码框之前、同一表单/容器、最近的可见文本框 | +25 | |
| 不可见（`display:none`、`visibility:hidden`、`opacity<0.1`、尺寸 < 4px、离屏） | 排除 | 排除 |

- 表单分组：优先 `<form>`；无 form 的 SPA 以“最近公共祖先容器 + 提交按钮”聚合。
- 两步登录：仅有用户名框（含 `autocomplete=username` 或有“下一步”按钮）时也视为登录表单；记录 tab 级状态，下一页出现密码框时继续填密码。
- 动态页面：`MutationObserver` 监听新增节点（节流 200 ms）；遍历**开放** Shadow DOM；同源 iframe 由各自 frame 中的内容脚本处理（`all_frames`）。
- 性能：首次扫描限制在 1000 个 input 内，使用 `requestIdleCallback`。

### 3.2 内联图标与菜单
- 在识别出的字段右侧叠加小图标（Shadow DOM 中的 closed 根，样式隔离）。
- 点击图标后注入 `inline-menu.html` 的 iframe（扩展源，`use_dynamic_url`），**条目标题/用户名只在扩展 iframe 内渲染**，页面脚本无法读取。
- 菜单项：匹配条目（标题、用户名、匹配标记如“子域名匹配”“⚠ 相似域名”）、“生成强密码”（new-password 字段）、“打开 PasswordManager 搜索”。
- 键盘可操作（↑↓ 回车 Esc），中文无障碍标签。

### 3.3 填充
1. 用户选择条目（或快捷键 Ctrl+Shift+L：唯一匹配直接填，多条弹菜单）。
2. background 向桌面发送 `credentials.get`，桌面复核后返回用户名、密码（及可选 TOTP）。
3. background 用 `tabs.sendMessage(tabId, msg, { frameId })` 只发给目标 frame。
4. 内容脚本：`focus()` → 通过原生 setter（`Object.getOwnPropertyDescriptor(HTMLInputElement.prototype,'value').set`）赋值 → 派发 `input`、`change`（React/Vue 兼容）→ `blur`；填充后立即丢弃字符串引用。
5. 可选自动提交（条目或全局开关，默认关）：点击表单的提交按钮而非 `form.submit()`。
6. 填充前最终检查：字段仍可见、frame 的 Origin 未变化（防止导航竞态）。

### 3.4 页面加载自动填充
默认**关闭**。开启后仅在：唯一匹配、`domain/host` 规则精确命中、顶层 frame、HTTPS、无任何告警时才自动填充（不自动提交）。

## 4. 手动输入后保存/更新凭据（捕获与提示）

> 通用规则（新建/已有判断、四种操作、密码历史、多账号）见 01 §3.6；本节描述浏览器端如何**捕获**以及如何**提示**。

### 4.1 表单类型判定
内容脚本在识别阶段（§3.1）为每个表单分组标注类型：

| 类型 | 判定信号 |
|---|---|
| `login` | 1 个密码框（`current-password` 或无 autocomplete）+ 0/1 个用户名框 |
| `login-step1` | 只有用户名框（`autocomplete=username`/email），有“下一步/继续”按钮，无密码框 |
| `login-step2` | 只有密码框；用户名取自同一 tab 上一步暂存的值（§4.4），或页面上只读/隐藏的 `autocomplete=username` 字段 |
| `signup` | `new-password`；或 2 个密码框且输入值相同（新密码+确认）；或页面文本/按钮含 注册/创建账号/Sign up |
| `change-password` | 3 个密码框（旧/新/确认）；或 2 个密码框值不同且其一为 `current-password` 或标签含 旧/原/当前密码；或 `autocomplete=new-password` 与 `current-password` 同时存在 |
| `reset-password` | 只有新密码+确认，URL/文本含 reset/重置/找回（无旧密码） |

改密表单字段分配：`current-password` 优先作为旧密码；否则按 DOM 顺序第一个为旧密码；“新密码”和“确认密码”取值相同者；若新≠确认，不提示（用户输入有误）。

### 4.2 值的采集
- 对识别出的字段监听 `input`/`change`（隔离世界中的监听器，页面脚本无法读取），在内容脚本内存中维护**最近一次非空值**快照：`{username, password, oldPassword?, newPassword?}`。
- 仅当字段值并非本扩展刚刚填充的值（记录填充时的值哈希）时才算“手动输入”；自动填充后用户改了密码 → 仍算手动输入。
- 很多站点提交时会清空密码框或用 JS 加密后替换，因此以“提交前最后一次非空快照”为准，不在提交后读取 DOM。

### 4.3 提交捕获信号
| 信号 | 实现 | 说明 |
|---|---|---|
| 原生表单提交 | 捕获阶段监听 `submit` 事件（`document.addEventListener('submit', h, true)`） | 最可靠 |
| 点击提交按钮 | 捕获阶段 `click`/`pointerup`：`button[type=submit]`、`input[type=submit]`、或文本/aria-label 含 登录/登陆/提交/确定/下一步/Sign in/Log in/Continue/保存 的按钮及 `role=button` 元素 | 覆盖无 form 的 SPA |
| 回车 | 密码框/用户名框上 `keydown` Enter | |
| SPA 路由变化 | background `webNavigation.onHistoryStateUpdated` / `onReferenceFragmentUpdated` | `pushState` 型登录跳转 |
| XHR/fetch 登录请求完成 | background `webRequest.onCompleted`（只观察，不拦截，不读取请求体）：同一 tab、快照后 10 秒内、方法 POST/PUT、状态 2xx/3xx、与表单同一可注册域 | 作为“可能登录成功”的辅助证据；不注入页面主世界 hook fetch（避免与页面冲突与被篡改） |
| 表单消失 | `MutationObserver`：密码框被移除或变为不可见 | 典型 SPA 登录成功表现 |
| 页面导航 | `webNavigation.onCommitted`（同 tab，顶层 frame） | 传统整页提交 |

判定流程：
```
任一“提交意图”信号（submit / 按钮 / 回车）
   → 内容脚本将快照 + 表单类型 + frameId 发给 background（附 formId）
   → background 结合浏览器提供的 Origin 暂存（按 tab，5 分钟过期；tab 关闭/保险库锁定即清除）
   → 等待“结果”信号（导航、路由变化、表单消失、POST 完成）最多 10 秒
       ├─ 有结果信号 → 进入提示（§4.5）
       ├─ 10 秒内无结果且表单仍在、页面出现错误文案（密码错误/验证码错误/incorrect/invalid，在表单附近 role=alert 或红色提示）→ 判定登录失败，不提示，保留快照等待下一次提交覆盖
       └─ 10 秒内无任何信号 → 仍提示，但采用“轻量提示”（图标角标 + 弹出窗口内的“保存刚才输入的账号”）
```
- 跨域登录（OAuth/SSO：表单在 `passport.example.com`，提交后跳到 `www.example.com`）：以**捕获时表单所在 frame 的 Origin** 作为保存的 URI；提示条显示在提交后的顶层页面并注明“来自 passport.example.com 的登录”。
- iframe 内的登录表单：同样按 frame 的 Origin 保存；若与顶层不同可注册域，提示中明确显示 frame 的域名。

### 4.4 两步登录
- `login-step1` 提交时只暂存用户名（tab 级，5 分钟）；`login-step2` 提交时把用户名与密码合并为一次捕获。
- 若第二步发生在不同可注册域，不合并（防跨站拼接），仅保存密码并让用户填写用户名。

### 4.5 判断与提示
background 发送 `entry.compare{origin, formType, username, password, oldPassword?}`，桌面端在 Core 中判断并返回（不回传任何已存密码）：

| 返回 `state` | 场景 | 提示条内容 | 按钮 |
|---|---|---|---|
| `new` | 无匹配条目 | “是否将 **alice** 的账号保存到 PasswordManager？（github.com）” | [保存] [本站从不] [忽略] |
| `new-account` | 本站已有其它账号 | “保存 github.com 的新账号 **bob**？本站已有 1 个账号” | [保存为新账号] [更新已有 ▼] [本站从不] [忽略] |
| `same` | 用户名+密码均与某条目相同 | 不提示 | — |
| `changed` | 用户名相同、密码不同 | “**alice** 的密码似乎已更改，是否更新？” | [更新] [另存为新条目] [忽略] |
| `changed-pw-form` | 改密表单；旧密码与某条目一致（或本站仅一条目） | “是否将 **GitHub（alice）** 的密码更新为新密码？” | [更新] [选择其它条目 ▼] [忽略] |
| `ambiguous` | 用户名为空/改密表单定位不到唯一条目 | “更新哪个账号的密码？” 下拉列出本站所有条目 + “新建” | [确定] [忽略] |

- 更新时旧密码进入 `passwordHistory`（01 FR-C6）；若条目尚无当前站点 URI，则同时追加。
- 提示条：在“结果信号”后的页面 `complete` 时向顶层 frame 注入 `notification-bar.html`（扩展源 iframe，页面不可读写其内容）；60 秒无操作自动收起为工具栏图标角标，弹出窗口中仍可处理，5 分钟后丢弃。
- **本站从不**：`settings.neverSave` → 按可注册域写入 `neverSaveDomains`。
- **忽略**：仅丢弃本次快照。
- `signup` 类型：若密码为扩展生成器生成（§3.2），保存默认已勾选并直接显示“已为 xxx 生成并保存密码？”。
- 保险库锁定：提示条显示“解锁以保存”，点击 → 桌面端解锁窗口 → 解锁后继续（暂存仍在有效期内）。
- 保存前由桌面端再次校验 Origin 与 `neverSaveDomains`；写入后推送 `vault.changed`。

### 4.6 手动添加
弹出窗口提供“添加当前网站账号…”：预填当前标签页 Origin 与标题，用户填写用户名/密码（或使用生成器），用于检测不到提交的非标准页面。

### 4.7 隐私
- 快照只在内容脚本与 background 内存中，从不写入 `storage`；tab 关闭、跨可注册域导航超过 5 分钟、保险库锁定、扩展会话断开时清除。
- 不观察请求体；`webRequest` 仅用于“同 tab 的 POST 是否完成”这一事实。
- 在 `neverSaveDomains` 中、或页面为 `http:`（默认设置“不在 HTTP 页面提示保存”可改）时不捕获。

## 5. 弹出窗口（Popup）
| 区域 | 功能 |
|---|---|
| 状态栏 | 已连接 / 桌面应用未运行 / 未配对 / 保险库已锁定（点击“解锁”→ 桌面端弹出解锁窗口并置前） |
| 当前站点 | 显示可注册域名与匹配条目；每条有 [填充] [复制用户名] [复制密码] [复制 TOTP] |
| 搜索 | 全库搜索（`entry.search`，仅返回摘要；300 ms 防抖） |
| 底部 | 生成密码、打开桌面应用、锁定、设置 |

复制：发送 `clipboard.copy{entryId, field}`，由**桌面端**写剪贴板并 30 秒后清除（扩展无法可靠在 SW 中定时清除剪贴板，也不排除剪贴板历史）。Popup 不显示明文密码（可按住“显示”按钮临时请求）。

## 6. URL / 域名匹配规则

### 6.1 规范化
1. 只接受 `http:`/`https:`（其它如 `file:`、`chrome:`、`about:` 不填充；`about:blank`/`srcdoc` frame 继承父 Origin）。
2. 主机名转小写、去尾点，IDN 转 punycode（UTS #46）。
3. IP 地址与 `localhost`：不做可注册域计算，按主机 + 端口精确匹配。
4. 默认端口归一（http 80 / https 443）。

### 6.2 可注册域名（eTLD+1）
- 使用 Mozilla **公共后缀列表（含 PRIVATE 段）**：`a.b.example.co.uk` → `example.co.uk`；`alice.github.io` → `alice.github.io`（github.io 为私有后缀，不同用户互不匹配）。
- PSL 随桌面应用/Android 应用版本发布（构建时下载并记录版本），扩展不需要自行更新。

### 6.3 匹配模式
| 模式 | 条目 URI 示例 | 匹配 | 不匹配 |
|---|---|---|---|
| `domain`（默认） | `https://github.com` | `github.com`、`gist.github.com`、`a.b.github.com` | `github.com.evil.cn`、`notgithub.com`、`github.io` |
| `host` | `https://login.example.com` | `login.example.com`（端口须一致，若 URI 指定了端口） | `www.example.com`、`example.com` |
| `startsWith` | `https://example.com/app/` | `https://example.com/app/login` | `https://example.com/application` |
| `exact` | `https://example.com/login` | 完全一致（忽略 fragment） | 带查询串 |
| `regex` | `^https://([a-z]+\.)?corp\.example\.com/` | 高级用户；UI 警告；正则在桌面端以超时限制执行 | |
| `never` | | 永不匹配（用于排除某子域） | |

附加规则：
- **协议**：条目 URI 为 https 时，http 页面视为“弱匹配”——不自动填充，菜单中带“⚠ 非安全连接”，需二次确认。
- **子域排除**：同一条目可同时含 `domain: example.com` 与 `never: https://user-content.example.com`，`never` 优先。
- **等价域名**：`settings.equivalentDomains`（如 `google.com` ↔ `youtube.com`），视为同一可注册域；内置少量常见组，用户可编辑。
- **排序**：exact > startsWith > host > domain 精确主机 > domain 子域 > 等价域；同级按最近使用时间。

### 6.4 反钓鱼保护
| 机制 | 说明 |
|---|---|
| 无子串匹配 | 永远不以 “URL 包含 github” 判断 |
| 只信任浏览器提供的 Origin | 不读取 `location.href` 自报值作为依据 |
| 同形字/混合脚本 | 主机含非 ASCII 时：比较 punycode；若混合多种文字（拉丁+西里尔等）或 UTS #39 骨架与已保存域名相同但实际不同 → 红色告警，禁止一键填充 |
| 相似域名告警 | 当前可注册域与任一已保存可注册域编辑距离 ≤ 2 或仅 TLD 不同（`github.co`）且无匹配条目时，弹出“这可能是仿冒网站”提示，只允许在桌面端手动确认后填充 |
| 跨域 frame | frame 与顶层不同可注册域：菜单显示“此表单来自 xxx”，需显式确认；绝不自动填充 |
| 表单目标 | `form.action` 指向不同可注册域或 http 时提示 |
| 不可见字段 | 不填充（防隐藏字段收集） |
| 用户手势 | 除“页面加载自动填充”严格条件外，一切填充都需点击/快捷键 |
| 桌面端复核 | `credentials.get` 时桌面端用同一 Origin 再次运行匹配，结果不一致则拒绝（防扩展被篡改后越权取任意条目） |

### 6.5 测试向量 `testvectors/url-match.json`

## 7. Native Messaging 协议

### 7.1 传输
- 帧：4 字节**本机字节序**（x86 为小端）长度 + UTF-8 JSON；宿主→扩展单条 ≤ 1 MB，扩展→宿主 ≤ 64 MiB（本协议实际 ≤ 64 KiB）。
- NativeHost 启动参数：Chrome/Edge 传入调用方 `chrome-extension://<id>/`（以及 Windows 上的 `--parent-window=`）；Firefox 传入清单路径与扩展 ID。NativeHost 校验其在白名单内，并把 `{browser, extId}` 作为元数据附在管道连接握手中。
- NativeHost 通过命名管道 `\\.\pipe\PasswordManager.<UserSID>.ext` 连接桌面应用，验证服务端进程（`GetNamedPipeServerProcessId` → 映像路径位于安装目录且 Authenticode 签名一致），然后原样转发帧。

### 7.2 明文控制消息（加密前）
`hello{protoVersions, extVersion}` → `hello.ack{protoVersion, appVersion, paired:bool}`；配对与会话消息见 03 §4.3–4.4。除此之外的所有消息都在加密信封中。

### 7.3 加密信封内的请求（扩展 → 桌面）
| type | 参数 | 返回 |
|---|---|---|
| `status.get` | — | `{locked, otpLocked, vaultName}` |
| `vault.unlock.request` | — | 桌面弹出解锁窗口；结果通过事件返回 |
| `match.query` | `topOrigin, frameOrigin, formType` | 条目摘要 `[{id,title,username,matchKind,warnings[]}]`（无密码） |
| `otp.match` | `topOrigin, frameOrigin` | 匹配的动态码项摘要 `[{otpId, issuer, account, icon, period}]`（无码值、无密钥）；动态码库锁定时返回 `OTP_LOCKED` |
| `totp.get` | `otpId, topOrigin, frameOrigin` | `{code, remaining, period}`（从不返回密钥；Origin 复核同 `credentials.get`；计入速率限制；动态码库锁定返回 `OTP_LOCKED`） |
| `credentials.get` | `entryId, topOrigin, frameOrigin, fields[]` | `{username,password}`（动态码改由 `totp.get` 从独立动态码库获取）；复核失败返回 `ORIGIN_MISMATCH` |
| `entry.search` | `query, limit≤50` | 摘要列表 |
| `entry.compare` | `topOrigin, frameOrigin, formType, username, password, oldPassword?` | `state`（new / new-account / same / changed / changed-pw-form / ambiguous）+ `candidates[{id,title,username}]`（不含密码） |
| `entry.save` | `origin, username, password, title?, mode（new / update）, entryId?` | `{entryId}`；update 时旧密码入 `passwordHistory` |
| `entry.addManual` | `origin, title, username, password` | `{entryId}` |
| `generate.password` | `policy?` | `{password}` |
| `clipboard.copy` | `entryId, field` | `{ok, clearAfterSec}` |
| `settings.neverSave` / `neverFill` | `domain` | `{ok}` |

### 7.4 事件（桌面 → 扩展）
`vault.locked`、`vault.unlocked`、`vault.changed{entryIds}`、`fill.trigger{reason:"hotkey"}`（全局热键时前台为该浏览器）、`save.trigger`（Ctrl+Alt+S 时前台为该浏览器 → 对当前页显示保存提示/手动添加）、`pairing.revoked`。

### 7.5 错误码
`APP_NOT_RUNNING`、`NOT_PAIRED`、`LOCKED`、`OTP_LOCKED`（动态码库锁定）、`USER_DENIED`、`ORIGIN_MISMATCH`、`RATE_LIMITED`（`credentials.get` 每分钟 ≤ 30 次）、`BAD_REQUEST`、`INTERNAL`。

## 8. 宿主注册（由 Windows 安装器完成，写 HKCU，无需管理员）
| 浏览器 | 注册表键（默认值 = 清单 JSON 绝对路径） |
|---|---|
| Chrome | `HKCU\Software\Google\Chrome\NativeMessagingHosts\com.passwordmanager.host` |
| Edge | `HKCU\Software\Microsoft\Edge\NativeMessagingHosts\com.passwordmanager.host` |
| Firefox | `HKCU\Software\Mozilla\NativeMessagingHosts\com.passwordmanager.host` |

Chromium 清单：
```json
{ "name": "com.passwordmanager.host", "description": "PasswordManager 本地宿主",
  "path": "C:\\Users\\<u>\\AppData\\Local\\Programs\\PasswordManager\\pm-native-host.exe",
  "type": "stdio",
  "allowed_origins": ["chrome-extension://<商店ID>/", "chrome-extension://<Edge 商店ID>/"] }
```
Firefox 清单相同但以 `"allowed_extensions": ["passwordmanager@<域名>"]` 代替 `allowed_origins`。Chrome、Edge 分别用各自清单文件（便于 Edge 商店 ID 不同）。卸载时删除键与文件。

## 9. 首次使用与配对流程（用户视角）
1. 安装桌面应用 → 安装扩展（商店链接在桌面应用“浏览器”页）。
2. 扩展首次打开显示“连接 PasswordManager” → 点击后桌面端弹出“新的浏览器请求配对：Microsoft Edge（扩展 v1.0）确认码 **482 913**”。
3. 用户核对扩展弹窗中的确认码一致 → 在桌面端点“允许”。
4. 完成；之后浏览器重启自动重连，无需再次配对。桌面端“浏览器”页可查看/撤销。

## 10. 与桌面自动输入的协同
- 桌面 Watcher 发现前台窗口属于已连接扩展的浏览器进程（NativeHost 的父进程 PID 即浏览器进程）时：全局热键 → `fill.trigger` 事件 → 扩展填充当前标签页；不再 SendInput。
- 前台为已连接浏览器时按 Ctrl+Alt+S → `save.trigger` → 对当前页显示保存提示（有快照时）或“添加当前网站账号”。
- 未安装扩展的浏览器：沿用 UIA 读取地址栏 + 自动输入，UI 中标注“地址未经扩展校验”。

## 11. 隐私与商店合规
- 无网络请求、无远程代码、无统计；权限说明（中文）列出 `<all_urls>` 用途（识别登录表单）。
- 发布：Chrome Web Store、Microsoft Edge 加载项、Firefox AMO（需签名）；固定扩展 ID 写入宿主清单。企业可通过组策略 `ExtensionInstallForcelist` 部署。

- 单元：字段打分器与表单类型判定（JSDOM 夹具：常见中文站点登录/注册/改密页快照，如邮箱、银行、论坛、SPA）、URL 匹配向量、信封/握手（与 Rust pm-core 互测向量）。

## 13. 动态码（TOTP）填充
> 通用设计见 08。动态码保存在桌面端的**独立动态码库**中；扩展从不接触密钥，只通过 `otp.match` 获得匹配项摘要、通过 `totp.get` 获得当前码与剩余秒数。动态码库锁定时显示“在桌面应用中解锁动态码库”。

### 13.1 OTP 输入框识别
| 信号 | 分值 |
|---|---|
| `autocomplete="one-time-code"` | +100 |
| name/id/placeholder/aria-label/标签含 otp、totp、2fa、mfa、two-factor、authenticator、verification code、动态码、动态口令、身份验证器、安全码 | +40 |
| `inputmode="numeric"` 或 `type=tel/number`，且 `maxlength` 为 6 或 8 | +30 |
| 同一容器内 6/8 个相邻 `maxlength=1` 输入框（分格输入） | 视为一个 OTP 组 |
| 页面文本含“短信验证码/发送验证码/邮箱验证码/图形验证码” | −60（多为短信/图片验证码，非 TOTP） |
| 同页存在密码框 | −30（通常为登录第一步） |
- 只有当前站点存在**匹配的动态码项**（`otp.match` 非空，或动态码库锁定但用户已开启“锁定时也提示”）时才显示 OTP 字段图标，避免误识别短信验证码框。

### 13.2 填充流程
1. 字段内联图标/菜单显示“填充 GitHub 动态码”（不显示码值），或快捷键 Ctrl+Shift+L 在 OTP 页面优先填动态码。
2. background → `totp.get`；桌面端若剩余 < 3 秒则等待下一周期后返回。
3. 填充：单框直接赋值；分格输入逐格赋值并派发 `input`/`keyup` 事件（部分站点按键事件驱动跳格）；不自动提交（可在条目中开启）。
4. **登录后自动衔接**：同一 tab 中刚用某密码条目填充过密码，且 2 分钟内同一可注册域出现 OTP 框 → 内联菜单默认选中 `linkedEntryId` 指向该条目的动态码项（关联关系由桌面端解析，扩展只拿到 otpId）；可选设置“填充密码后自动将动态码复制到剪贴板”（默认关，因剪贴板风险，见 03 T22）。
5. 反钓鱼：与密码相同的 Origin 规则（§6）；相似域名、同形字、跨域 iframe 中**禁止**动态码一键填充。

### 13.3 弹出窗口
- “动态码”分区显示当前网站匹配的**精简卡片**（08 §11.8）：图标、“发行方: 账号”、`●●● ●●●`、“N秒”+圆形进度，按钮 [显示] [复制] [✦ 填充到网页]；码值默认隐藏，点按显示 5 秒（浏览器弹窗无法防截屏）；不提供全库浏览。
- 复制由桌面端执行（过期或 30 秒内清除，排除剪贴板历史）。
- “添加动态码”：引导到桌面应用的“从屏幕扫描二维码”（扩展本身不读取页面图像，避免申请额外权限）。

### 13.4 事件
- 桌面热键 Ctrl+Alt+T 且前台为该浏览器 → `totp.fill.trigger` 事件 → 扩展对当前活动标签页的 OTP 框执行 §13.2。
