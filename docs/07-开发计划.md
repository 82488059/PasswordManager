# 07 开发计划

## 1. 里程碑总览（以 1 名全栈开发者计，单位：周）

> 技术路线：**Qt 6 / QML**（Windows + Android 一套界面）+ C++ 适配层 pm-qt + Rust `pm-core`/`pm-win`（cxx 桥接）+ Kotlin 原生模块（自动填充/生物识别/SAF，UniFFI + JNI）+ TypeScript 扩展（02 §5–§7）。

合计约 **37 周**（Flutter 版 35.5 周）。变化说明：
- **更省的部分**：桌面多窗口（Picker、保存气泡、迷你浮窗）与托盘由 Qt 原生支持，M2a 3.5 → 3 周，并消除了 Flutter 多窗口的主要风险。
- **更贵的部分**：Qt for Android 构建链与自定义 Gradle/Kotlin 集成、Corrosion/cxx 桥接与 C++ 模型层（M0 +0.5、M2 +0.5 周）；Android 平台能力需经 JNI，且自动填充流程中的保存确认/选择界面需以原生 Kotlin 实现（M3 +0.5 周）；LGPL 合规与 Qt 部署（M9 +0.5 周）。
- 若团队熟悉 Qt/C++ 但不熟悉 Rust，可评估 02 §6.2 的“C++ 核心”退路：M1 约 −0.5 周（与 Qt 同语言），但需 +1.5 周手写 Kotlin JNI 绑定并重新评估安全措施，总体不更快。

## 2. 依赖关系
```
M0 → M1 → M2 → M2a → M2b
        │    │    └→ M4 → M5 → M6
        │    └→ M3 ───────────→ M7
        └→（pm-core TOTP 可提前）
M2 + M5 + M7 → M7b
M2a + M3 → M8 → M9（M2b、M6、M7、M7b 完成后）
```
- compare、URL 匹配、TOTP、合并在 pm-core 中只实现一次，Windows、Android（以及经桌面端的扩展）天然一致。
- M2（QML 共用界面）完成后，M2a（Windows）与 M3（Android）可由两人并行。

## 5. 风险
| 风险 | 影响 | 缓解 |
|---|---|---|
| Chromium MV3 SW 回收 | 填充延迟、保存快照丢失 | 原生端口保活；快照随提交即发往 background，SW 重启前提示 |
| 各站点表单与登录流程千差万别 | 识别/保存失败或误提示 | 打分器可调；登录失败抑制；“手动添加”兜底；夹具持续迭代 |
| Windows 原生应用读不到密码 | 用户需二次输入密码 | 对话框说明原因、支持粘贴；Ctrl+Alt+S 手动入口；坚持不使用键盘钩子 |
| UIA 在自绘/游戏/Electron 应用中不可用 | 无法检测登录 | 手动保存入口；Auto-Type 仍可用 |
| IME / UIPI 导致 Auto-Type 失败 | 输错或无反应 | IME 临时关闭、VK/Unicode 切换、完整性级别检测与提示 |
| Android 兼容模式保存不可靠 | 浏览器中不提示保存 | UI 标注；手动添加；推荐使用原生支持的浏览器 |
| 同步工具行为差异、SAF 无原子写 | 冲突或数据损坏 | 冲突副本自动合并、写后校验、历史版本 |
| 商店审核（`<all_urls>`、nativeMessaging、webRequest） | 上架延迟 | 最小权限说明；无远程代码 |
| 同一用户下的恶意软件 | 无法完全防御 | 明确写入范围外 |
| Qt 许可证（LGPLv3 义务 / 商业许可成本） | 合规风险或预算 | M0 即做决策；只用 LGPL 模块、动态链接、提供许可证文本与替换说明；需要静态链接或官方 LTS 支持时购买商业许可（02 §7） |
| Qt for Android 集成（单 QtActivity、JNI、Gradle 模板定制、APK 体积） | Android 进度延误、包体变大 | 自动填充界面用原生 Kotlin；JNI 帮助类保持少而稳定；按 ABI 拆分 AAB；裁剪未用 Qt 模块 |
| Rust + C++ + Kotlin 三语言、Corrosion/cxx 构建复杂 | 进度延误、调试困难 | M0 先打通脚手架与 CI；桥接接口保持小而稳定（句柄 + ID）；退路见 02 §6.2 |
| QML `QString` 中的秘密无法清零 | 内存残留 | 秘密默认不出 Rust；UI 按需获取、尽快释放（03 §3） |
| 全局热键插件与前台窗口快照时序 | 自动输入目标错误 | 前台快照在原生侧完成；必要时由 pm-win `RegisterHotKey` 接管 |
| 两个库两套密码增加使用负担 | 用户嫌麻烦或设成相同密码 | 两库各自可用生物识别快速解锁；相同密码校验拒绝；向导说明独立的意义 |
| 界面与知名身份验证器过于相似 | 商标/商业外观风险 | 自有图标与名称、可换主题色、品牌图标仅用于识别服务（08 §11.10） |
| OTP 框与短信验证码框难以区分 | 误填/打扰 | 仅在有匹配的动态码项时提示；短信验证码负分 |
| 设备时间不准 | 动态码无效 | 时间同步检测与手动校准 |
