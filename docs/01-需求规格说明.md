# 01 需求规格说明

## 1. 目标
构建一个本地优先、端到端加密的密码管理器，覆盖 **Windows 桌面应用、Windows 上的浏览器（Chrome / Edge / Firefox）、Android 应用与 Android 浏览器**，能够：
1. 统一保存、管理账号密码等凭据；
2. 自动识别当前正在使用的应用或网站；
3. 在需要登录时自动填充用户名和密码，并在登录新账号时提示保存。

## 2. 用户与场景
| 场景 | 描述 |
|---|---|
| S1 桌面应用登录 | 在 Windows 打开某客户端（如 QQ、游戏启动器），按热键或在密码框聚焦时弹出提示，自动输入账号密码 |
| S2 浏览器网页登录 | 在 Chrome/Edge/Firefox 打开登录页，扩展在用户名/密码框旁显示图标，点击即填充；匹配多条时可选择 |
| S3 手动输入后保存/更新 | 用户在网页、Windows 应用或 Android 应用中手动输入账号密码登录（或修改密码）后，系统识别这是新账号还是已有账号，提示“保存 / 更新 / 此站点（应用）从不 / 忽略” |
| S4 浏览器快速查找 | 点击工具栏图标打开弹出窗口，搜索条目，复制用户名/密码/动态码 |
| S8 动态码（2FA） | 在类似身份验证器 App 的“动态码”页点 ＋ 扫描网站两步验证二维码或导入 Google 身份验证器，之后在登录第二步自动填充 6 位动态码，或点击卡片上的码复制；动态码保存在独立的动态码库中 |
| S5 Android 应用登录 | 打开 App 的登录页，系统自动填充下拉中出现匹配条目，解锁后填入 |
| S6 Android 浏览器登录 | 在 Chrome / Firefox / Samsung Internet 等浏览器中打开网页登录，按网页域名匹配并填充 |
| S7 多端同步 | 通过网盘/文件复制/局域网同步同一个加密保险库文件 |

## 3. 功能需求

### 3.1 保险库与条目（通用）
- FR-V1 主密码解锁；支持 Windows Hello / Android 生物识别作为快速解锁（包装密钥，不替代主密码）。
- FR-V2 条目字段：标题、用户名、密码、**URI 列表（每条带匹配规则）**、Windows 应用标识（进程名 / exe 路径 / 窗口标题模式）、Android 包名（+ 可选签名证书指纹）、备注、TOTP 密钥、标签、创建/更新时间、`autofillOnPageLoad`（三态：继承全局 / 开 / 关）、`passwordHistory`（旧密码历史，默认保留 10 条）。动态码密钥**不在**密码条目中，而保存在独立动态码库（见 3.7）。
- FR-V3 增删改查、搜索、标签过滤、密码生成器（长度、字符集、易读模式、口令短语）。
- FR-V4 空闲自动锁定、系统锁屏/休眠时锁定；剪贴板复制后自动清除（默认 30 秒）。
- FR-V5 全局“从不填充 / 从不保存”的域名与应用排除列表（`neverFillDomains`、`neverSaveDomains`、`neverFillApps`、`neverSaveApps`、`neverSaveAndroidPackages`）。

### 3.2 Windows 桌面端
- FR-W1 托盘常驻；前台窗口识别（进程、标题）；对浏览器窗口，**若该浏览器已连接扩展则交由扩展处理**，否则回退到 UI Automation 读取地址栏 URL。
- FR-W2 全局热键（默认 Ctrl+Alt+A）自动输入，序列可配置，如 `{USERNAME}{TAB}{PASSWORD}{ENTER}`；多条匹配弹出选择器。
- FR-W3 **Native Messaging 宿主**：安装时为 Chrome、Edge、Firefox 注册宿主清单；处理扩展的查询、填充、保存、生成密码、复制请求。
- FR-W4 **扩展配对管理**：显示配对请求与 6 位确认码；列出已配对浏览器（名称、浏览器类型、配对时间、最后使用），可撤销。
- FR-W5 对扩展请求的授权策略：保险库锁定时弹出解锁窗口；可选“每次填充前确认”。
- FR-W6 原生应用手动输入后保存/更新：基于 UIA 检测密码框聚焦 + 登录提交（Enter/点击登录按钮/登录窗口关闭或切换），弹出预填应用身份与可读用户名的保存/更新对话框；**密码由用户在对话框中输入或粘贴**（不读取原窗口密码、默认不使用键盘钩子）。另提供热键 Ctrl+Alt+S 与托盘“保存当前应用凭据…”。详见 3.6 与 04 §7。

### 3.3 浏览器扩展（Chrome / Edge / Firefox，Manifest V3）
- FR-B1 内容脚本识别登录表单：密码框、用户名框（基于 `autocomplete`、`type`、`name/id`、标签文本等启发式），支持 SPA 动态表单、开放 Shadow DOM、同源 iframe、两步登录（先用户名后密码）。
- FR-B2 在识别到的字段内显示内联图标；点击后显示匹配条目菜单（菜单在扩展自有 iframe 中渲染，页面脚本不可读取）。
- FR-B3 一键填充用户名 + 密码；可选填充后自动提交（默认关）；支持快捷键（默认 Ctrl+Shift+L）与右键菜单填充。
- FR-B4 工具栏弹出窗口：显示当前站点匹配条目、全库搜索、复制用户名/密码/TOTP（复制由桌面端完成以便自动清除）、打开桌面应用、锁定。
- FR-B5 保存/更新提示：检测表单提交、SPA/XHR 登录、修改密码表单（旧/新/确认）后，提示“保存 / 更新 / 本站从不 / 忽略”，写入桌面端保险库（规则见 3.6，细节见 05b §4）。
- FR-B6 注册页（`autocomplete="new-password"`）提供“生成强密码”建议，由桌面端生成。
- FR-B7 URL/域名匹配规则：默认按可注册域名（eTLD+1，基于公共后缀列表）匹配并包含子域名；可按条目改为“主机精确”“前缀”“完全一致”“正则”“从不”。端口与协议参与判断。
- FR-B8 反钓鱼保护：不使用子串匹配；IDN 同形字检测与 punycode 显示；与已保存域名的相似度告警；不向不可见字段填充；跨域 iframe 填充需用户显式确认；HTTPS 保存的凭据不在 HTTP 页面自动填充；表单提交目标跨域时警告。
- FR-B9 扩展**不存储保险库**、不缓存凭据；仅保存配对密钥与少量设置。桌面应用未运行或未配对时，提示用户启动/配对。
- FR-B10 桌面端锁定/解锁、条目变更时，扩展实时收到事件并刷新状态图标。

### 3.4 Android 端
- FR-A1 AutofillService：按请求方包名 + 签名证书匹配应用条目。
- FR-A2 **浏览器填充**：读取 `ViewNode.getWebDomain()`/`getWebScheme()`，按与扩展相同的 URL 匹配规则匹配网站条目；支持原生实现自动填充框架的浏览器（Chrome 需在设置中选择“使用其他服务自动填充”、Firefox、Samsung Internet、Brave 等）。
- FR-A3 **兼容模式**：在服务配置中声明 `compatibility-package`，为不支持自动填充框架的浏览器启用基于无障碍的兼容模式，从地址栏解析域名。
- FR-A4 仅信任白名单浏览器（包名 + 签名证书指纹）上报的网页域名；其它 App 内 WebView 的域名需通过 Digital Asset Links 关联校验，否则按 App 自身包名匹配。
- FR-A5 填充前需解锁（BiometricPrompt / 主密码）；Android 11+ 支持输入法内联建议。
- FR-A6 手动输入后保存/更新：通过 SaveInfo / onSaveRequest 实现，系统保存界面确认后由本应用区分新建与更新（详见 3.6 与 05 §5）。

### 3.5 同步
- FR-S1 同一加密文件可在 Windows/Android 间同步；冲突时按条目级合并（见 06）。


### 3.6 手动输入后保存/更新凭据（跨平台）
适用于：浏览器网页（扩展）、Windows 原生应用、Android 应用与 Android 浏览器。

- FR-C1 **捕获时机**：用户手动输入凭据并提交登录/注册/修改密码时触发；本应用自动填充后用户未修改的提交不提示。
- FR-C2 **新建 vs 已有判断**（在桌面端/Android Core 中执行，不把旧密码交给扩展）：
  | 情况 | 判定 | 默认提示 |
  |---|---|---|
  | 当前站点/应用无匹配条目 | 新账号 | 保存 |
  | 有匹配条目，用户名相同、密码相同 | 已保存 | 不提示 |
  | 有匹配条目，用户名相同、密码不同 | 密码已更改 | 更新 |
  | 有匹配条目，但用户名都不同 | 同一站点的另一个账号 | 保存为新条目（可改选“更新某个已有条目”） |
  | 用户名为空/读不到（两步登录、Windows 读不到时） | 不确定 | 让用户选择新建或更新哪一条 |
  | 修改密码表单（旧/新/确认） | 改密 | 更新（以旧密码或用户名定位条目） |
- FR-C3 **四种操作**：
  - **保存**：新建条目，自动填入标题（站点名/应用名）、用户名、密码、URI（`match=domain`）或应用标识（进程名+路径 / 包名+证书）。
  - **更新**：更新所选条目的密码（或用户名），并补充当前站点/应用的匹配规则。
  - **此站点/应用从不**：加入 `neverSave*` 列表，以后不再提示，可在设置中撤销。
  - **忽略**：本次不处理，不记住。
- FR-C4 **密码变更检测**：比较时去除首尾空白以外不做任何归一化；密码比较在受信端（桌面/Android）以常量时间进行，结果仅以“相同/不同”返回。
- FR-C5 **同一站点多账号**：一个站点/应用可有多个条目；提示框中列出该站点所有账号供选择“更新哪一个”；填充时多条匹配进入选择器。
- FR-C6 **密码历史**：更新密码时旧密码连同时间写入 `passwordHistory`（默认保留最近 10 条，可设 0–50），条目详情可查看/复制历史密码；历史随保险库加密与同步。
- FR-C7 **锁定状态**：保险库锁定时先暂存（内存，最长 5 分钟），提示解锁后继续保存；超时丢弃。
- FR-C8 **平台限制须在 UI 中如实说明**：Windows 原生应用无法读取密码框内容，需用户在保存对话框中再次输入或粘贴密码；Android 兼容模式下保存可能不触发；网页中部分非标准登录（Canvas、跨域 iframe 内）可能检测不到，可用弹出窗口“手动添加当前网站”。

### 3.7 动态码（2FA / TOTP）管理
详细设计见 [08-动态码TOTP设计](08-动态码TOTP设计.md)。
- FR-T0 **存储（默认）**：动态码密钥保存在**独立的动态码库 `otp.pmv`**，使用**独立的动态码库密码**（不得与主密码相同）、独立 Vault Key、独立自动锁定（默认 5 分钟）与独立的快速解锁；同步位置单独设置（建议与密码保险库不同，或仅保存在手机）。“与密码同库存储”仅作为**高级、不推荐**选项，需主密码确认与风险提示。
- FR-T1 动态码项字段：`secret`（Base32）、算法（SHA1 默认 / SHA256 / SHA512）、位数（6 默认 / 8）、周期（30 秒默认）、发行方与账号标签、图标、置顶、匹配网站/应用规则、可选关联的密码条目（仅记录在动态码库中）。TOTP（RFC 6238）为主，兼容 HOTP（RFC 4226）与 Steam Guard 5 位码。
- FR-T2 导入：`otpauth://` URI、`otpauth-migration://`（Google 身份验证器导出，含多张二维码批次）、二维码（Windows：图片文件/剪贴板/屏幕框选/摄像头；Android：相机/相册）、手工输入 Base32、Steam `shared_secret`。导入时去重、建议关联密码条目，并支持与原验证器比对校验。
- FR-T3 显示：类身份验证器 App 的卡片列表（08 §11）——发行方图标 + “发行方: 账号”、大号分组动态码、复制按钮、可选快捷操作按钮、“N秒”+圆形进度、临近过期预显示下一个码；深色主题绿色强调色（跟随系统可切换浅色）；可设置默认隐藏码值。
- FR-T4 交互：点击动态码即复制；右下角 ＋ 悬浮按钮添加（扫码 / 屏幕扫描 / 图片 / 粘贴链接 / 手动输入 / Google 身份验证器导入）；搜索（含拼音首字母）；置顶收藏与拖动排序；⋮ 菜单（编辑、置顶、关联密码条目、查看密钥/导出需复核、时间校准、删除）；空状态引导。
- FR-T5 复制与填充：复制（过期或 30 秒内自动清除剪贴板）；Windows Auto-Type `{TOTP}` 与热键 Ctrl+Alt+T；浏览器识别 OTP 输入框（`autocomplete="one-time-code"`、分格输入框等）并填充，弹出窗口显示当前网站的精简动态码卡片；Android 自动填充识别 OTP 字段并提供动态码数据集。剩余 < 3 秒时等待下一个码。动态码库锁定时提示单独解锁。
- FR-T6 安全：独立库加密（强度同密码保险库）；永不写日志；剪贴板自动清除并排除剪贴板历史；显示动态码时启用系统防截屏（Windows `WDA_EXCLUDEFROMCAPTURE`、Android `FLAG_SECURE`）；动态码库锁定时不显示任何发行方/账号；明文导出需重新输入动态码库密码且默认不含密钥；浏览器扩展只接收动态码不接收密钥。
- FR-T7 时钟：检测系统时间未自动同步并告警；导入验证采用 ±1 周期窗口；可选手动时间校准（设备本地）。
- FR-T8 同步：`otp.pmv` 按 06 的机制独立同步；`totp` 作为整体合并，HOTP 计数器取最大值；两库互不依赖。

## 4. 非功能需求
| 编号 | 需求 |
|---|---|
| NFR-1 安全 | 保险库 AES-256-GCM + Argon2id；扩展通道配对 + 加密；明文凭据在内存中尽快清零 |
| NFR-2 隐私 | 无云端账号、无遥测；扩展不访问网络（无远程代码，符合 MV3 要求） |
| NFR-3 性能 | 浏览器中从点击图标到填充完成 < 300 ms（已解锁）；表单识别对页面加载影响 < 10 ms |
| NFR-4 兼容 | Windows 10 22H2+ / 11；Chrome & Edge 116+，Firefox 128+（MV3）；Android 9（API 28）+（Qt 6.8 的最低支持版本；兼容模式同样需 API 28） |
| NFR-5 可用性 | 所有 UI 文案简体中文；扩展支持 `_locales/zh_CN` |
| NFR-6 可测试 | 加密、URL 匹配、保存判定、同步合并、TOTP 均有共享测试向量（Rust 核心统一校验，扩展相关部分由 TypeScript 校验） |
| NFR-8 技术约束 | Windows 与 Android 使用**同一个 Qt 6 / QML 应用**作为界面（C++ 适配层）；核心逻辑为单一 Rust 库（经 cxx 供 C++、经 UniFFI 供 Kotlin）；Windows 系统集成在 Rust `pm-win` 与 Qt 中实现，Android 自动填充等为 Kotlin 原生代码；浏览器扩展独立（TypeScript）。Qt 以 LGPLv3 动态链接使用（或购买商业许可）。详见 02 §5–§7 |
| NFR-7 不做键盘记录 | Windows 端默认不安装全局键盘钩子；任何读取用户输入的能力仅限 UIA 公开的非密码字段 |
