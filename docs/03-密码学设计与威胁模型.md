# 03 密码学设计与威胁模型

## 1. 密钥层次

```
主密码 ──Argon2id(salt, m=64 MiB, t=3, p=4)──► KEK (32B)
                                               │ AES-256-GCM 解包
随机 Vault Key (32B) ◄─────────────────────────┘
   │
   └─ AES-256-GCM 加密 JSON 负载 ─► vault.pmv

动态码库密码（≠ 主密码）──Argon2id(独立 salt)──► OTP KEK ──解包──► 独立随机 OTP Vault Key
   └─ AES-256-GCM 加密动态码负载 ─► otp.pmv（默认；见 08 §1）

快速解锁：Windows Hello / Android Keystore(生物识别绑定) 包装 Vault Key 的副本，仅存本机，不同步；OTP Vault Key 使用**另一把**独立的快速解锁密钥。
扩展配对密钥：与 Vault Key 无关，见 §4；仅用于本机扩展 ↔ 桌面通道。
```

- KDF：Argon2id 默认参数如上；低端 Android 可降至 m=32 MiB（参数写入文件头，读取方按头部参数计算）。保留 `PBKDF2-SHA256, 600 000 次` 作为兼容 KDF ID。
- 更换主密码只需重新包装 Vault Key，不重新加密负载。

## 2. 保险库文件格式（vault.pmv，两端共用）

| 偏移 | 长度 | 字段 |
|---|---|---|
| 0 | 4 | 魔数 `PMV1` |
| 4 | 2 | 格式版本（uint16 LE，当前 1） |
| 6 | 1 | KDF ID（1=Argon2id，2=PBKDF2-SHA256） |
| 7 | 12 | KDF 参数（m KiB / t / p，或 iterations），uint32 LE ×3 |
| 19 | 16 | salt |
| 35 | 12 | wrap nonce |
| 47 | 48 | 被包装的 Vault Key（32B 密文 + 16B tag） |
| 95 | 12 | payload nonce |
| 107 | n | payload 密文 + 16B tag |

- 整个头部（0–106 字节）作为两次 GCM 的 AAD，防止参数被篡改降级。
- 每次保存生成新的 payload nonce；Vault Key 永不复用 nonce（随机 96 位，单库保存次数远低于碰撞界限）。

### 2.1 负载 JSON（节选，与浏览器相关字段）
```json
{
  "schema": 1,
  "entries": [{
    "id": "uuid", "title": "GitHub", "username": "alice", "password": "…",
    "uris": [
      { "uri": "https://github.com", "match": "domain" },

    ],
    "autofillOnPageLoad": null,
    "windowsApps": [{ "process": "GitHubDesktop.exe", "titlePattern": null }],
    "androidApps": [{ "package": "com.github.android", "certSha256": ["…"] }],
    "tags": [], "notes": "", "created": "…", "updated": "…",
    "passwordHistory": [{ "password": "旧密码", "retiredAt": "2026-10-05T04:30:00Z" }],
    "autoType": { "sequence": null, "mode": "unicode", "delays": null }
  }],
  "settings": {

```
同步相关字段（`vaultId`、`revision`、`keyEpoch`、`fieldTimes`、墓碑 `deleted/deletedAt`）见 06 §1。

`match` 取值：`domain`（默认，可注册域名 + 所有子域）、`host`（主机名完全一致，可选端口）、`startsWith`、`exact`、`regex`、`never`。规则详见 05b §6。

## 3. 内存与剪贴板
- 解锁后的明文**只驻留在 Rust `pm-core` 内存**中（`zeroize::Zeroizing`/`SecretString`，锁定或释放时清零；可行时 `mlock`/`VirtualLock` 防止换页）。自动输入、剪贴板、扩展响应、Android 数据集均在 Rust/Kotlin 原生侧直接取值，不经过 C++/QML。
- C++（pm-qt）与 QML 只在用户主动显示/编辑时取得单个字段：C++ 侧以 `QByteArray` 暂存并在用完后安全清零（`SecureZeroMemory` / `explicit_bzero`）；一旦进入 QML 成为 `QString`（隐式共享、可能被复制），**无法保证清零**——UI 层通过“按需获取、离开页面即清空属性、密码框 `echoMode: TextInput.Password`、不进入日志与撤销历史”降低残留时间（02 §6.4）。Kotlin 侧仅在构建 `AutofillValue` 时持有 `CharArray`，用后填零。
- QML 显示的发行方、账号、标题等来自不可信输入（二维码、网页保存），一律使用 `Text.PlainText`，禁止 RichText/StyledText，防止标签注入与外链加载。
- 待保存凭据（浏览器快照、Windows 保存对话框暂存、Android PendingSave）：仅内存，≤5 分钟，锁定即清除，从不落盘。
- 密码条目中**不含**动态码字段；动态码密钥默认保存在独立的 `otp.pmv`（同一文件格式，负载 `kind: "otp"`，结构见 08 §1.2），使用独立密码与独立 Vault Key，设置时校验其不能与主密码相同。
- 动态码密钥 `totp.secret` 与 `totpHistory` 与密码同等对待：负载加密、解码后的字节计算完即清零、只缓存当前周期的码；日志/审计/崩溃信息中永不出现密钥、otpauth URI 或动态码（见 08 §7）。
- 密码历史 `passwordHistory` 与当前密码同等对待（同一负载加密、同步、清零）；删除条目时一并清除。
- 剪贴板：Windows 写入时设置 `ExcludeClipboardContentFromMonitorProcessing` 与 `CanIncludeInClipboardHistory=0`、`CanUploadToCloudClipboard=0`，30 秒后若内容未变则清空。扩展的“复制”一律委托桌面端执行。

## 4. 浏览器扩展通道（Native Messaging 之上的加密层）

### 4.1 为什么在 Native Messaging 之上再加密
Native Messaging 已经限制只有清单中 `allowed_origins`/`allowed_extensions` 列出的扩展能拉起宿主，但仍存在：
- 同名“山寨”扩展被侧载、或开发模式下扩展 ID 被复用；
- 其他本地进程尝试连接桌面应用的命名管道；
- 宿主清单注册表项被替换为恶意程序（中间人）。
因此桌面应用**不信任 stdio/管道本身**，而是信任“已配对的扩展实例的密钥”。这是纵深防御；对于已在同一用户下取得任意代码执行能力的恶意软件，本方案只能提高门槛（见 §6 范围外）。

### 4.2 算法（全部为 WebCrypto 原生支持，扩展无需加密库）
- 密钥协商：ECDH P-256（扩展侧 `crypto.subtle`，`extractable: false`，CryptoKey 存 IndexedDB）。X25519 在浏览器普及后可作为 v2 套件。
- KDF：HKDF-SHA256。
- AEAD：AES-256-GCM。
- 摘要：SHA-256。

### 4.3 配对（一次性，SAS 短码确认，抗中间人）
```
扩展 E                                        桌面 D
生成静态密钥对 (sE, SE)，随机 nE(32B)
── pair.commit { C = SHA256(SE ‖ nE), browser, extId, label } ──►
                                              生成/加载静态密钥 (sD, SD)，随机 nD
◄── pair.challenge { SD, nD } ─────────────────
── pair.reveal { SE, nE } ───────────────────►  校验 C
双方计算 SAS = uint32(SHA256("PM-SAS-v1" ‖ SE ‖ SD ‖ nE ‖ nD)[0..4]) mod 10^6
扩展弹窗显示 6 位码                              桌面显示 6 位码 + 浏览器/扩展信息
                                              用户在**桌面端**点击“一致，允许”
◄── pair.ok { pairingId } ─────────────────────  保存 {pairingId, SE, extId, browser, label}
保存 {pairingId, SD}
```
- 先承诺后揭示，攻击者无法在看到对方公钥后挑选密钥去碰撞 SAS（成功率 ≤ 10⁻⁶ 每次尝试）。
- 配对请求 60 秒超时；连续 3 次拒绝后 10 分钟内不再接受配对请求。
- 桌面端配对记录存于本机 `%LOCALAPPDATA%\PasswordManager\pairings.json`，以 DPAPI（CurrentUser）保护，**不进入保险库、不同步**。

### 4.4 会话建立（每次连接/SW 重启）
类似 Noise KK：
```
E → D: session.open { pairingId, EE(临时公钥), tsE }
D → E: session.accept { ED(临时公钥), tsD, mac }
ikm = ECDH(eE,ED) ‖ ECDH(sE,ED) ‖ ECDH(eE,SD) ‖ ECDH(sE,SD)
(k_e2d, k_d2e, sid) = HKDF(ikm, salt = SHA256(EE‖ED), info = "PM-SESSION-v1")
mac = HMAC(k_d2e, "accept" ‖ transcript)；E 回 session.confirm{HMAC(k_e2d,"confirm"‖transcript)}
```
- 双方静态密钥均参与，实现相互认证；临时密钥提供前向保密。
- 会话最长 12 小时；保险库锁定**不**终止会话（仅状态变化），撤销配对立即终止。

### 4.5 消息信封
```json
{ "v": 1, "sid": "base64(8B)", "seq": 42, "ct": "base64(AES-GCM(json))" }
```
- nonce = 方向(4B: `E2D\0`/`D2E\0`) ‖ seq(uint64 BE)；AAD = `v ‖ sid ‖ seq`。
- 接收方要求 `seq` 严格递增，拒绝重放与乱序；解密失败立即断开并记录。
- 明文负载 ≤ 64 KiB（远小于宿主→扩展 1 MB 上限）。

### 4.6 扩展侧存储边界
| 存储位置 | 内容 |
|---|---|
| IndexedDB | 静态私钥（不可导出 CryptoKey）、pairingId、桌面公钥 SD |
| `storage.local` | UI 设置（是否显示内联图标、快捷键提示等） |
| 内存（SW/背景页） | 会话密钥、待保存凭据（≤5 分钟）、当前标签页匹配摘要（无密码） |
| **从不** | 保险库文件、Vault Key、主密码、密码列表缓存 |

## 5. 威胁模型

### 5.1 资产
主密码、动态码库密码、Vault Key、OTP Vault Key、明文凭据、动态码密钥（TOTP/HOTP/Steam）及生成的动态码、“哪些账号开启了 2FA”的元数据、配对私钥、会话密钥。

### 5.2 攻击者与对策

| # | 攻击者 / 场景 | 风险 | 对策 |
|---|---|---|---|
| T1 | 窃取 vault.pmv（网盘泄露、设备丢失） | 离线暴力破解 | Argon2id 高成本参数；头部 AAD 防降级；鼓励强主密码（强度计） |
| T2 | 钓鱼站点（`githuh.com`、`github.com.evil.cn`） | 诱导填充 | PSL 可注册域名匹配，禁用子串匹配；相似域名告警（编辑距离 ≤2 / 同形字骨架一致）；默认不在页面加载时自动填充 |
| T3 | IDN 同形异义（`gіthub.com` 西里尔 і） | 视觉欺骗 | 统一转 punycode 比较；混合脚本域名在 UI 中显示 `xn--` 形式并告警 |
| T4 | 恶意/被 XSS 的子域名（`evil.example.com`） | `domain` 规则下也会匹配 | 文档提示；PSL 私有段（如 `github.io`、`blogspot.com`）视为独立可注册域；用户可对条目改用 `host` 精确规则；敏感条目建议 `host` |
| T5 | 跨域恶意 iframe 嵌入合法页面 | 在 iframe 中套取凭据 | 只向 Origin 与条目匹配的 frame 填充；顶层与 frame 不同可注册域时需显式确认；绝不跨 frame 传值 |
| T6 | 页面隐藏字段、点击劫持 | 静默收集凭据 | 只填充可见、可交互、尺寸合理的字段；内联菜单在扩展 iframe 中渲染并检测遮挡（IntersectionObserver v2 可用时）；页面加载自动填充默认关闭 |
| T7 | HTTP 页面 / 网络中间人 | 凭据被截获 | 条目保存为 https 时，http 页面不自动填充且需确认；表单 action 指向 http 或跨域时警告 |
| T8 | 页面脚本伪造 URL / 篡改内容脚本消息 | 欺骗匹配 | Origin 只取浏览器提供的 `sender.tab.url`/`sender.url`/`sender.origin`；内容脚本运行于隔离世界；不使用 `window.postMessage` 传递敏感数据 |
| T9 | 山寨扩展 / 恶意本地进程连接宿主或管道 | 冒充扩展取凭据 | 宿主清单仅列出官方扩展 ID；命名管道 ACL 仅当前用户 SID 且 `FILE_FLAG_FIRST_PIPE_INSTANCE`；桌面端校验客户端为签名的 NativeHost.exe；**配对 + 加密通道**是最终授权依据 |
| T10 | 宿主清单被替换（中间人宿主） | 窃听/篡改流量 | 流量端到端加密，中间宿主只能看到密文；无法伪造会话（无配对私钥） |
| T11 | 其他已安装的恶意扩展 | 可读取已填入页面的值 | 无法完全防御（浏览器模型限制）；文档告知；填充后不在 DOM 留额外痕迹 |
| T12 | Android 恶意 App 在自身视图中伪造 `webDomain` | 冒充网站取凭据 | 仅信任白名单浏览器（包名 + 签名证书 SHA-256）上报的 webDomain；其它 App 的 WebView 需 Digital Asset Links 关联，否则仅按包名匹配 |
| T13 | Android 兼容模式（基于无障碍）被滥用 | 读取屏幕内容 | 兼容模式由系统框架实现，本应用不申请无障碍权限；可选 AccessibilityService 回退默认关闭，并明确风险提示 |
| T14 | 内存取证 / 同用户恶意软件 | 读取明文 | 自动锁定、缓冲区清零、最小驻留；超出范围见 5.3 |
| T15 | 为实现“手动输入后保存”而安装全局键盘钩子 | 本应用变成键盘记录器；被利用后泄露所有输入；杀软误报 | **不使用键盘钩子**（v1 不提供）；Windows 只用 UIA 事件判断“发生了登录”，密码由用户在本应用对话框中输入/粘贴；UIA 只读取非密码字段（用户名） |
| T16 | 恶意网页伪造“保存密码”提示条，诱导输入主密码 | 主密码泄露 | 真提示条在扩展源 iframe 中且**从不要求输入主密码**（解锁一律在桌面应用窗口进行）；文档与首次引导中明确告知 |
| T17 | 恶意网页/应用触发虚假“更新”提示以污染已有条目（把 github 的密码改成攻击者值） | 用户锁死自身账号 / 后续误填 | `entry.compare`/`entry.save` 仅可作用于与**浏览器提供的 Origin**（或已验证的包名/证书）匹配的条目；更新需用户点击；旧密码保留在 `passwordHistory` 可回退 |
| T18 | 在钓鱼站点手动输入后保存 | 钓鱼域名被加入条目，日后自动匹配 | 相似域名/同形字告警同样作用于保存提示（“此站点与 github.com 相似，确定保存？”）；默认作为**新条目**保存而非追加到相似域名的已有条目 |
| T19 | 浏览器保存捕获被其他页面读取 | 凭据泄露 | 快照只在隔离世界与 background 内存；`webRequest` 只观察，不读请求体；跨可注册域不合并两步登录 |
| T20 | Android 恶意 App 伪造保存请求（伪装 webDomain） | 将凭据关联到错误站点 | 与 T12 同：仅可信浏览器/DAL 验证的 WebView 才能以网页域名保存，否则以 App 包名+证书保存 |
| T21 | 密码保险库被攻破（主密码泄露 + 文件泄露） | 若动态码同库，2FA 退化为单因素 | **默认独立动态码库**：`otp.pmv` 独立密码/独立 Key/独立同步位置，密码保险库中不含任何动态码信息（含关联关系）；同库存储仅为不推荐的高级选项并有风险提示；高价值账号建议 FIDO2/Passkey |
| T22 | 剪贴板监视恶意软件读取复制的动态码 | 在有效期内被实时冒用 | 优先直接填充/Auto-Type；复制时排除剪贴板历史/云剪贴板，过期或 30 秒内清除；可设置禁止复制动态码 |
| T23 | 实时中间人钓鱼（AitM 反向代理，如仿冒登录页索要动态码） | 动态码被实时转发使用；TOTP 本身不抗钓鱼 | 动态码填充与密码一样受 Origin 匹配约束，相似域名/同形字页面阻止填充并告警；用户手动复制粘贴到未匹配站点时无法阻止 → 文档说明并推荐 Passkey |
| T24 | 截屏/录屏/屏幕共享/肩窥 | 动态码与密钥二维码泄露 | Windows `WDA_EXCLUDEFROMCAPTURE`、Android `FLAG_SECURE`；可选默认隐藏动态码；密钥（Base32）默认不显示，查看需重新验证 |
| T25 | 2FA 二维码截图残留在相册/下载目录 | 任何人可扫描获得密钥 | 本应用不保存二维码图像；导入完成后提示删除源图片 |
| T26 | 恶意/畸形二维码或 URI（超长、非法参数） | 解析器崩溃或注入 | 严格解析与长度上限（URI ≤ 4096、protobuf 字段上限）；不跟随任何链接；未知参数忽略；QML 中以纯文本显示（禁止富文本） |
| T27 | 明文导出/备份文件泄露 | 全部动态码密钥泄露 | 默认只做加密导出；明文导出需主密码复核与风险确认，默认不含动态码密钥 |
| T28 | 系统时间被篡改或漂移 | 动态码无效（拒绝服务） | 时间同步检测与告警；±1 周期导入校验；手动校准仅本机生效 |
| T29 | 扩展被篡改后批量请求动态码 | 获取任意账号当前动态码 | `totp.get` 与 `credentials.get` 同样要求 Origin 复核与速率限制；扩展从不获得密钥 |
| T30 | 用户为动态码库设置与主密码相同（或可推导）的密码；两库放在同一网盘目录 | 独立库的隔离效果丧失 | 设置时用候选密码尝试解包主库 Key，相同则拒绝；向导默认建议不同同步位置或“仅手机”；同目录时显示提示 |

### 5.3 范围外
- 已获得同一 Windows 用户/管理员权限、可注入浏览器或桌面进程、键盘记录的恶意软件。
- 被 Root 的 Android 设备、被篡改的浏览器本体。
- 用户在 SAS 不一致时仍点击“允许”。

## 6. 测试向量
所有向量由 pm-core 的 `cargo test` 统一校验（核心只有一份实现）；扩展侧的 TypeScript 代码校验与其相关的 channel / url-match 向量。

`testvectors/crypto.json`：Argon2id/PBKDF2 → KEK、包装/解包、完整 vault 文件的 hex；`testvectors/channel.json`：固定密钥下的 SAS、HKDF 输出、信封密文（Rust 与 TypeScript 校验）；`testvectors/url-match.json`：见 05b §6.5（Rust 与 TypeScript 校验）；`testvectors/save-compare.json`：保存/更新判定（new / new-account / same / changed / changed-pw-form / ambiguous，Rust）；`testvectors/merge.json`：同步三方合并（见 06 §10）；`testvectors/totp.json`：RFC 6238/4226 向量、otpauth / otpauth-migration 解析、Steam 编码（见 08 §9）。
